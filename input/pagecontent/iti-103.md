This section describes the national extension for the Health Dossier to the
[Get Authorization Server Metadata [ITI-103]](https://profiles.ihe.net/ITI/IUA/index.html#3103-get-authorization-server-metadata-iti-103)
transaction defined in the IUA profile.

### Scope

An IUA Authorization Client or IUA Resource Server retrieves the metadata of the IUA Authorization Server, e.g., the
token endpoint for the [Get Access Token [ITI-71]](iti-71.html) transaction, the registration endpoint for the
[Client Registration](client-registration.html) and the key material to verify the signature of the access tokens.

### Actor Roles

**Actor:** Authorization Client or Resource Server  
**Role:** Sends a request to the Authorization Server to retrieve the Authorization Server metadata.  
**Actor:** Authorization Server  
**Role:** Responds with the Authorization Server metadata.  

### Referenced Standards

1. [IHE ITI Technical Framework Supplement Internet User Authorization (IUA) Revision 2.5](https://profiles.ihe.net/ITI/IUA/index.html)
2. [RFC 8414: OAuth 2.0 Authorization Server Metadata](https://www.rfc-editor.org/rfc/rfc8414)
3. [RFC 8615: Well-Known Uniform Resource Identifiers (URIs)](https://www.rfc-editor.org/rfc/rfc8615)

#### Authorization Server Metadata Request

##### Trigger Events

An IUA Authorization Client (portal, primary system, digital health app or clinical archive system) or an IUA
Resource Server wants to retrieve the Authorization Server metadata (e.g., the token endpoint, the registration
endpoint or the key material required for the validation of the access token signature).

##### Message Semantics

The Authorization Client or Resource Server performs an HTTP GET request to the well-known metadata endpoint of the
Authorization Server, formed as defined in [RFC 8414, Section 3.1](https://www.rfc-editor.org/rfc/rfc8414#section-3.1). 
The request SHALL neither use parameter nor body data and SHALL NOT include client credentials.

##### Expected Actions

The Authorization Server SHALL respond with the [Authorization Server Metadata Response](#authorization-server-metadata-response).

##### Message Example

```http
GET /.well-known/oauth-authorization-server HTTP/1.1
Host: authz.example.com
```

#### Authorization Server Metadata Response

##### Message Semantics

The Authorization Server SHALL respond with an HTTP response conveying a JSON formatted object as HTTP body 
element, as defined in [RFC 8414, Section 2](https://www.rfc-editor.org/rfc/rfc8414#section-2). The JSON object SHALL
convey the following attributes:

| Attribute                             | Optionality | Reference      | Description                                                                                                                                                                                       |
|---------------------------------------|-------------|----------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| issuer                                | R           | RFC 8414 / IUA | The Authorization Server's issuer identifier, an https URL without query or fragment components.                                                                                                 |
| authorization_endpoint                | O           | RFC 8414 / IUA | URL of the authorization endpoint. Not used, since the Health Dossier uses the client credentials grant only.                                                                                    |
| token_endpoint                        | R           | RFC 8414 / IUA | URL of the token endpoint for the [Get Access Token [ITI-71]](iti-71.html) transaction.                                                                                                           |
| token_endpoint_auth_methods_supported | R           | RFC 8414       | Client authentication methods supported by the token endpoint. SHALL include `private_key_jwt`.                                                                                                   |
| registration_endpoint                 | O           | RFC 8414       | URL of the dynamic client registration endpoint, see [Client Registration](client-registration.html).                                                                                            |
| jwks_uri                              | R           | RFC 8414 / IUA | URL of the Authorization Server's JWK Set [RFC 7517, Section 5] document.                                                                                                                         |
| scopes_supported                      | O           | RFC 8414 / IUA | Recommended: Supported scopes.                                                                                                                                                                    |
| response_types_supported              | R           | RFC 8414 / IUA | Supported OAuth 2.1 response_type values.                                                                                                                                                         |
| grant_types_supported                 | R           | RFC 8414 / IUA | SHALL include `client_credentials`.                                                                                                                                                               |
| access_token_format                   | O           | IUA            | Array of JSON strings defining the format of the access token as provided by the Authorization Server. The array SHALL contain a single string with value `urn:ietf:params:oauth:token-type:jwt`. |
{:class="table table-bordered"}

<div><figcaption>Attributes of the Get metadata transaction</figcaption></div>  

##### Expected Actions

The Authorization Client SHALL use the `token_endpoint` for the [Get Access Token [ITI-71]](iti-71.html) transaction.
The Resource Server SHALL use the keys of the `jwks_uri` document to verify the signature of the access tokens.

##### Message Example

```json
{
  "issuer": "https://authz.example.com",
  "authorization_endpoint": "https://authz.example.com/authorize",
  "token_endpoint": "https://authz.example.com/token",
  "token_endpoint_auth_methods_supported": ["private_key_jwt"],
  "registration_endpoint": "https://authz.example.com/register",
  "jwks_uri": "https://authz.example.com/jwks.json",
  "scopes_supported": ["purpose_of_use", "subject_role"],
  "response_types_supported": ["code"],
  "grant_types_supported": ["client_credentials"],
  "access_token_format": ["urn:ietf:params:oauth:token-type:jwt"]
}
```
