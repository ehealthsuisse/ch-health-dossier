# CH Health Dossier

FHIR API to connect to the CH Health Dossier.

The national IHE extensions documented in this FHIR implementation guide shall be used in conjunction with the definitions of integration profiles, actors and transactions provided in Volumes 1 through 3 of the IHE IT Infrastructure Technical Framework.

### Structure Definitions

To support **conformance** to the IHE profiles, the following validation mechanisms are added in this implementation guide:
* The CH Health Dossier profiles check the conformity to the corresponding IHE profile using constraints if it cannot be derived (`conformsTo`)
* The examples are validated against both profiles (CH Health Dossier & IHE) (listed in `meta.profile`)

### Conformance Statements

The conformance statements are not marked in the markdown pages, they are listed separately:

* `input/data/conformance.json`: per page the statements in page order, with `id`, `actors`, optional `conditional`
  and `summary` (for blocks), and the exact markdown `text` they cover (`before` if the text is not unique on the page)
* `input/data/conformance-ignore.json`: sentences with SHALL/SHOULD/MAY that are not conformance statements per
  page, or `"*"` for a page that is not checked
* `local-template/`: local template based on `ch.fhir.ig.template` (`ig.ini`: `template = #local-template`) that puts
  the IG Publisher markers around these texts when the pages are rendered
  (`local-template/package/includes/conformance-markers.html`)
* `input/resources/Requirements-fromNarrative.json`: the statements as Requirements resource, generated by the IG
  Publisher

Check the statements (also run as a GitHub Action on pull requests):

```sh
python3 scripts/check_conformance.py                    # texts found on the pages, SHALL/SHOULD/MAY outside a statement
python3 scripts/check_conformance.py --suggest          # print the sentences found as new statements with the next free id
python3 scripts/check_conformance.py --suggest --write  # add them to conformance.json, then add the actors
python3 scripts/check_conformance.py --ignore           # accept the sentences found as non-statements
```

After changing a statement, update its `text` in `conformance.json` (the QA report shows a broken link
`conformance-statement-not-found-<id>.html` otherwise). If the build writes a new `Requirements-fromNarrative.json` to
the root, copy it to `input/resources/` and build again.
